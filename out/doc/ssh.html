ssh - Acton SSH module

This module exposes a callback-driven SSH client/server API built on libssh
and integrated with Acton's libuv loop. The main actors are:

- Client: connects to a server, reports on_connect(err) and on_close(reason),
and optionally on_hostkey(state, HostKeyInfo) for strict host key checks.
- Channel: client-side data stream (stdout/stderr/exit/close callbacks).
- RunCommand: convenience wrapper that buffers stdout/stderr and reports exit.
- Server: listens for incoming connections and creates ServerSession actors.
- ServerSession: per-connection state; emits on_auth(AuthRequest),
on_channel_open, and optional on_exec/on_subsystem.
- ServerChannel: server-side data stream for a single channel.

Usage sketch (client):
def on_connect(c, err):
if err is not None: ...
Channel(c, on_open, on_stdout, on_stderr, on_exit, on_close)

def on_hostkey(c, state, info):
if state == HOSTKEY_OK: c.accept_hostkey()
else: c.reject_hostkey("...")

Usage sketch (server):
def on_auth(sess, req): sess.accept_auth()
def on_channel_open(sess): sess.accept_channel(ServerChannel(...))
def on_subsystem(sess, ch, name): ch.accept_request(); ch.write(...)

Authentication (client):
- If private_key_file is set, public key authentication is attempted first.
- If password is set, password authentication is attempted (after pubkey,
if both are given).
- If neither is given, the connection fails.

Callback ordering and semantics:
- All operations are async actor actions; callbacks receive errors as ?str.
- ?bytes data callbacks use None to signal EOF (end of that stream).
- On channel teardown the delivery order is: on_exit (if the remote sent an
exit status), then on_stdout(None) / on_stderr(None) for streams that have
not seen EOF yet, then on_close(reason). on_close is always delivered
exactly once for channels that opened successfully.
- on_connect is delivered exactly once; on_close only after a successful
connect. Failures before that are reported through on_connect(err).

Flow control:
- Channel writes are buffered internally and flushed as the SSH window
opens. max_write_buffer (Client/Server) bounds the per-channel buffer;
when exceeded the channel is failed rather than buffering without bound.
A value of 0 disables the limit.

Notes:
- Timeouts and keepalive are configurable; server host keys are generated
in-memory unless host_key_path is set.
- Server admission limits are configurable; values <= 0 disable a limit.
- For debugging, set ACTON_SSH_DEBUG and ACTON_SSH_LIBSSH_LOG.

SSH Client

Connects to host:port as username. on_connect(err) fires exactly once:
err is None on success, otherwise a description of the failure.
on_close(reason) fires exactly once after a successful connect when the
session ends. on_hostkey is invoked for host key verification when the
key is not already trusted via known_hosts; respond with accept_hostkey()
or reject_hostkey(reason).

SSH Channel

A client-side SSH channel. After on_open(None), request exec/shell/
subsystem and write data. on_stdout/on_stderr deliver inbound data;
None signals EOF on that stream. on_exit delivers the remote exit
status (and signal name, if any). on_close(reason) is the final
callback for a successfully opened channel.

actor RunCommand(client: Client, cmd: str, on_exit: (Channel, int, ?str, bytes, bytes, ?str) -> None, timeout: ?float = None)

Run a command and collect output

Opens a channel, executes cmd, buffers stdout and stderr, and reports
once via on_exit(channel, exit_code, exit_signal, stdout, stderr, error).
error is None on success. If timeout is given, the command is aborted
and error="timeout" after that many seconds.

SSH Server

Listens on host:port. Use port=0 to bind a kernel-assigned ephemeral
port; query the actual port with bound_port() once on_listen has fired.
For each incoming connection a ServerSession actor is created; on_session
fires when it is ready. Authentication requests are delivered via
on_auth(session, AuthRequest); respond with session.accept_auth() or
session.reject_auth(reason). Channel opens are delivered via
on_channel_open(session); respond with
session.accept_channel(ServerChannel(...)) or session.reject_channel().

SSH Server Session

Server; applications receive it via on_session and the auth/channel
callbacks. All channel operations are delegated through this actor.

SSH Server Channel

A server-side SSH channel. on_data/on_stderr deliver inbound data; None
signals EOF. Use write/write_stderr to send data, send_exit_status to
report a command result and close() to finish.
